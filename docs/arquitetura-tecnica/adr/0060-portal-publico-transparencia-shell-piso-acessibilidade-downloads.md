# ADR-0060 · Portal público de transparência (RAZ-278): shell separado do back-office, piso de acessibilidade WCAG/eMAG, Lista+Totais com filtro compartilhado, duas affordances de download

- **Status:** Aceita (ratificado via confirmação no RAZ-278, 2026-08-03)
- **Data:** 2026-08-02
- **Contexto:** RAZ-273/ADR-0059 entregaram o consumidor real do outbox e a API pública da transparência ativa (`TransparenciaPublicaController`, sem sessão, ente vem do path `/transparencia/{enteId}/...`), mas ADR-0059 registrou explicitamente que "as telas do portal (WCAG 2.2 AA) são gate de UX separado: Paula entrega fluxo/wireframe sobre este contrato antes de qualquer código de tela". RAZ-278 é esse gate. Três forças em jogo:
  1. O portal é uma superfície **pública, sem sessão, path-scoped por ente** — estruturalmente diferente de toda tela de back-office já desenhada (nenhuma tem `Seletor de Ente` interativo nem opera sem `RequireAuth`).
  2. [05-acessibilidade.md](../../transversais/05-acessibilidade.md) já registra o **Design System gov.br** como piso recomendado especificamente para "o portal do cidadão" (não o back-office) — decisão que o [ADR-0026](./0026-design-system-figma-decisoes-estruturais.md) tinha adiado deliberadamente ("misturar os dois arquivos agora acopla uma decisão de tema cidadão a um entregável de back-office sem essa exigência"). RAZ-278 é o momento em que essa decisão precisa ser resolvida de verdade.
  3. O contrato real (`FiltroTransparenciaPublica`, `TotalizacaoTransparenciaPublica`, `CamposOrdenacaoTransparenciaPublica`, verificados no código) tem formato específico que o wireframe não pode contrariar: totalização agrupa só por `estagio`; ordenação restrita a 4 campos; paginação é keyset (sem números de página); `/despesas/bulk` devolve manifesto de um arquivo **não filtrado** por CDN; não existe endpoint de nome de exibição do ente nem busca por nome de credor/órgão.
- **Decisão:**
  1. **Shell público próprio, não reuso do shell do back-office.** Header/rodapé institucionais novos (`Header Institucional (Público)`, `Rodapé Institucional (Público)`), sem `Seletor de Ente` (o ente já vem do path) e sem a navegação principal do operador (`FeatureNav`/RAZ-233). Skip link, breadcrumb e landmarks são as únicas âncoras de navegação persistente.
  2. **Piso de acessibilidade = WCAG 2.2 AA/eMAG, não o kit gov.br/ds especificamente.** Verificado via `get_libraries` no Figma (fileKey `ObQu8oMQ0cEGbONMXgpuLU`): nenhuma biblioteca gov.br/ds está anexada nem disponível neste workspace (só Material 3, Simple Design System, kits Apple). Como [05-acessibilidade.md](../../transversais/05-acessibilidade.md) já registra que "o piso legal é a conformidade WCAG/eMAG, não o DS especificamente (o DS é meio, não obrigação)", o wireframe v1 reaproveita os tokens semânticos SIAFIC já validados em AA (mesmo contraste ≥7:1 auditado para o back-office, [design-system-tokens-componentes.md §1.2](../design-system-tokens-componentes.md#12-semânticos-coleção-color-1-modo-value)) em vez de importar um kit que não existe no ambiente. Anotações de a11y (aria-live na paginação/contagem, role="tab", landmarks, skip link) ficam documentadas nas telas para o código real aplicar. **Revisão futura deste ADR** se/quando a biblioteca gov.br/ds for anexada ao Figma.
  3. **Lista e Totais são a mesma tela, alternada por aba, não duas rotas com filtro duplicado.** Um único componente `Barra de Filtros — Transparência (compartilhada Lista/Totais)` alimenta as duas visões — implementa [UX-2/ADR-0059] literalmente (mesmos parâmetros de filtro, sem duas telas divergentes). O drill-down totalização→lista aplica o `estagio` da linha clicada preservando os demais filtros ativos, em vez de abrir uma tela nova zerada.
  4. **Duas affordances de download, rotuladas para não confundir:** "Exportar CSV desta consulta" (lista filtrada/paginada corrente, `GET /despesas?formato=csv`) é distinta de "Baixar base completa" (`GET /despesas/bulk`, arquivo versionado por CDN que **não aplica os filtros ativos** — confirmado no código: o nome do arquivo CDN é function de `enteId`+`versao`, não dos parâmetros de filtro). A tela de bulk (Tela 4) expõe um aviso explícito disso.
  5. **Gap de nome de exibição do ente não é fabricado.** O contrato só expõe `enteId` (UUID) no path; nenhum endpoint de nome/branding de ente existe hoje. Header e breadcrumb mostram `Ente {enteId}` literal com uma nota de gap, em vez de inventar um campo `nomeEnte`. Decisão de como resolver (registro estático no frontend, endpoint público novo, ou branding genérico sem nome) fica para Rafael/backend — não decidida aqui.
  6. **Totalização/ordenação não inventam granularidade que a API não tem.** A tela de Totais mostra só as 3 linhas de estágio + total geral (reflete `TotalizacaoTransparenciaPublica.Linha(estagio, valor, quantidade)`); o seletor "Ordenar por" lista só os 4 campos de `CamposOrdenacaoTransparenciaPublica`.
  7. **Entregável:** wireframes reais (não só ASCII) no Figma já existente do design system (`fileKey ObQu8oMQ0cEGbONMXgpuLU`), página nova `21 Portal Público — Transparência (RAZ-278)` — 2 componentes de shell, 1 barra de filtros compartilhada, 2 componentes de linha (resultado/totalização), 5 telas (Lista, Totais, Detalhe/drill-down, Dicionário de dados, Baixar base completa) e um frame `Documentation` com os gaps acima. Detalhe do inventário em [design-system-tokens-componentes.md §6](../design-system-tokens-componentes.md#6-portal-público-de-transparência-raz-278).
- **Consequências:** destrava a decisão de arquitetura de shell/rota pública que RAZ-278 pedia (Rafael pode desenhar a separação de rota sabendo que não há `Seletor de Ente`/nav interna a encaixar); mantém o portal honesto sobre 3 gaps reais de contrato (nome do ente, campo `função` sem descrição no dicionário-fonte, IDs opacos sem busca por nome) em vez de escondê-los atrás de UI que promete mais do que a API entrega; adia a adoção literal do kit gov.br/ds para quando a biblioteca existir no ambiente, sem violar o piso legal (WCAG/eMAG) enquanto isso. Custo: se/quando o gov.br/ds for anexado, as telas precisam de uma passada de retematização (não de redesenho de fluxo — a estrutura/IA já fica fixada por este ADR).
- **Alternativas consideradas:**
  - **Reusar o shell do back-office (Header/Nav do operador) também no portal público** — rejeitada: o portal não tem sessão nem ente-troca interativa; o shell do operador pressupõe as duas coisas (`RequireAuth`, `Seletor de Ente`), então reuso forçaria uma tela com controles que não fazem sentido sem login.
  - **Bloquear o wireframe até a biblioteca gov.br/ds estar disponível no Figma** — rejeitada: o piso legal é WCAG/eMAG, não o kit específico ([05-acessibilidade.md](../../transversais/05-acessibilidade.md)); esperar por uma biblioteca indisponível travaria RAZ-278 e, por consequência, a decisão de arquitetura de frontend que depende dele, sem ganho de conformidade real no meio tempo.
  - **Duas telas separadas para Lista e Totais, cada uma com seu próprio filtro** — rejeitada: contraria [UX-2] literalmente e arrisca os dois filtros divergirem com o tempo (mesmo risco que motivou o UX-2 no gate RAZ-272).
  - **Um único botão "Baixar CSV" cobrindo tanto o recorte filtrado quanto a base completa** — rejeitada: a API não tem uma rota que faça as duas coisas com o mesmo contrato (`/despesas?formato=csv` é paginado e filtrado; `/despesas/bulk` é um manifesto para arquivo completo não filtrado); um único botão enganaria o cidadão sobre o que ele está baixando.
