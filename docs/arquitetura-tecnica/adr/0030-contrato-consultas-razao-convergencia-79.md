# ADR-0030 · Convergência do contrato das consultas (RAZ-101) com RAZ-79 §6.1; o balancete é demonstrativo, não lista paginável

- **Status:** Aceita
- **Data:** 2026-07-26
- **Contexto:** RAZ-114 (levantado na RAZ-112, telas de consultas/relatórios) leu o código real das 3 consultas implementadas e testadas na RAZ-101 — `RazaoConsultaController` (`GET /api/v1/entes/{enteId}/razao/saldo` e `.../razao/balancete`) e `ExecucaoConsultaController` (`GET /api/v1/entes/{enteId}/execucao/orcamentaria`) — contra o contrato de API já ratificado na RAZ-79 (`fluxo-execucao-operador-contrato-api.md` §6.1, downstream de [ADR-0006](./0006-dinheiro-decimal.md)). Seis gaps: **três divergências do §6.1** — dinheiro serializado como número JSON (`BigDecimal` cru via Jackson) e não string decimal; envelope de erro `{"erro": "codigo"}` em vez de `{"codigo","mensagem","detalhes"}`; balancete sem paginação; **dois funcionais** — não há catálogo/busca de conta PCASP (o operador não tem como descobrir o `contaId` UUID que `/saldo` exige, embora `conta_pcasp` já exista e seja usada internamente por `ExecucaoContabilPortAdapter.resolverConta`), e `PostgresConsultaSaldoPort.saldoDevedorLiquido` devolve zero indistintamente para "conta sem lançamento" e para "conta inexistente"; **um informativo** — `LinhaBalancete`/`BalanceteResponse` não expõem `natureza_saldo`. A pergunta da triagem: RAZ-101 converge para o §6.1, ou o §6.1 cede (ex.: string-decimal só nos endpoints de escrita ainda não implementados)?
- **Decisão:**
  1. **As convenções do §6.1 vinculam leitura tanto quanto escrita — RAZ-101 converge, o §6.1 NÃO cede.** O §6.1 é o contrato ratificado de toda a superfície de API, não só dos endpoints de escrita. As consultas nasceram antes de o contrato ser lido e derivaram; a correção é nelas.
  2. **Dinheiro é string decimal de 2 casas também na leitura (gap 3).** O risco que a convenção evita — o cliente HTTP desserializar `128450.00` como float — é *inteiramente* de leitura: quem lê e parseia o valor é o cliente. A convenção se aplica *mais* à leitura que à escrita. As 3 respostas (`SaldoContaResponse`, `BalanceteResponse`, `ExecucaoOrcamentariaResponse`) devem serializar `Dinheiro` como `"128450.00"`. Mecanismo recomendado: um **serializer Jackson único de `Dinheiro`** (`valor().toPlainString()`, escala 2) registrado uma vez, com os DTOs carregando `Dinheiro` em vez de desembrulhar para `BigDecimal` cru — centraliza a garantia em todas as bordas, presentes e futuras. Enforcement de [ADR-0006](./0006-dinheiro-decimal.md)/§6.1, não decisão nova.
  3. **Envelope de erro único `{codigo, mensagem, detalhes}` (gap 4).** O `ErroResponse(String erro)` da RAZ-101 é exatamente a "segunda taxonomia na borda HTTP" que o §6.1 proíbe. Enforcement. Nota de implementação: `ErroContrato` hoje só expõe `codigo()`; `mensagem`/`detalhes` exigem enriquecer o contrato (defaults opcionais no `ErroContrato` ou mapeamento no handler) — desenho pequeno, não um rename. No mesmo passo, corrigir o *status* do `mfa_requerido`: `ErroContratoExceptionHandler` devolve `403`, o §6.1 ratifica `428` (*Precondition Required*).
  4. **O balancete é um demonstrativo contábil, NÃO uma "lista" do §6.1 — não adota o cursor `{itens, proximoCursor}` (gap 5).** Duas razões: (a) sua totalização (`totalMovimentoDebito/Credito` e `confere` = Σdébito=Σcrédito) é propriedade do conjunto *completo*; um envelope paginado ou perderia esses agregados de cabeçalho/rodapé, ou tornaria `confere` não-confiável por página. (b) O racional do cursor no §6.1 é explícito sobre *coleções append-only ilimitadas deslizando sob escrita concorrente* ("uma lista que cresce o tempo todo"); o conjunto de contas PCASP de um período é *limitado e estável* (PCASP analítico ~milhares de linhas no teto; balancete mensal de ente pequeno, centenas). Logo o §6.1 não governa o balancete e **não há divergência a corrigir** — o balancete fica como está, single-payload, sem cursor. O que se corrige é a *documentação*: o §6.1 passa a distinguir explicitamente **demonstrativo** (cabeçalho + linhas + rodapé Σ/`confere`) de **lista** paginada, para que a ausência de cursor não seja lida como omissão. Se o tamanho de payload virar problema *medido*, a resposta é export/streaming de relatório — preocupação de relatório, não cursor de lista.
  5. **`LinhaBalancete`/`BalanceteResponse.Linha` expõem `natureza_saldo` (gap 6).** `conta_pcasp.natureza_saldo` (`char` D/C) existe; a UI precisa da natureza *natural* da conta — não do sinal do `saldoAtual` (uma conta devedora com saldo credor é uma anomalia que a UI tem de poder *sinalizar*, não inferir). Vai junto da convergência (gaps 3/4).
  6. **Catálogo/busca de conta PCASP é endpoint novo, com escopo próprio (gaps 1 e 2).** `GET /api/v1/entes/{enteId}/razao/contas?busca=&cursor=&limit=` — este SIM é uma *lista* do §6.1 (adota `{itens, proximoCursor}`, cursor opaco, `limit` default 20/máx 100), tenant-scoped por RLS (`app.ente_id`). Devolve `{id, codigo, descricao, naturezaSaldo, naturezaInformacao, escrituravel, contaPaiId}`; `busca` casa prefixo de `codigo` **ou** `descricao ilike`. Precisa de um **read port novo** em `razao-domain` (+ adapter Postgres) lendo a mesma `conta_pcasp` que `ExecucaoContabilPortAdapter.resolverConta` já usa. A validação de existência (gap 2) reusa esse read: `ConsultarSaldo` valida a conta no ente e lança `conta_nao_encontrada` (404) quando ela não existe; zero fica só para conta *existente* sem lançamento. Delegado a issue filha de backend própria (escopo próprio: busca + paginação + hierarquia).
- **Consequências:**
  - Gaps 3, 4, 6 (+ `mfa_requerido`→428) = enforcement de convenção já ratificada; issue filha **[BACKEND] convergência**. Sem mudança de comportamento de domínio — só serialização e borda HTTP; os testes (`RazaoConsultaControllerTest`, `ExecucaoConsultaControllerTest`, `ErroContratoExceptionHandlerTest`) passam a asserir string-decimal e o envelope `{codigo,…}`.
  - Gap 5 = doc/ADR apenas; **nenhum retrabalho de código** (o balancete permanece single-payload, sem cursor).
  - Gaps 1, 2 = issue filha **[BACKEND] catálogo PCASP + validação de existência**; read port novo em `razao-domain`, coerente com [ADR-0007](./0007-read-models-cqrs.md) (read model derivado).
  - O contrato doc ganha §6.7 (consultas do razão/execução — RAZ-101) e o §6.1 passa a nomear "demonstrativo vs lista".
- **Alternativas consideradas:**
  - **§6.1 cede: string-decimal só na escrita.** Rejeitada — o hazard de float é de *leitura*; ceder deixaria justamente os endpoints que o cliente parseia expostos ao bug que a convenção existe para evitar.
  - **Paginar o balancete como lista `{itens, proximoCursor}`.** Rejeitada — quebra a totalização (`confere`), que é propriedade do conjunto todo, e aplica um racional (coleção append-only sob escrita concorrente) que não vale para um demonstrativo de período limitado.
  - **Um único endpoint/issue para tudo.** Rejeitada — o catálogo PCASP (busca + paginação + hierarquia, read port novo) tem escopo e superfície próprios; misturá-lo com o rename de serialização das consultas existentes entangla dois changesets independentes.
