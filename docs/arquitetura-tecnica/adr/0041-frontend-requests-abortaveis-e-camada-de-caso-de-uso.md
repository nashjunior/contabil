# ADR-0041 · Frontend: requests abortáveis (AbortSignal) e camada de caso de uso separada do hook

- **Status:** Aceita
- **Data:** 2026-08-01
- **Contexto:** RAZ-137 pede dois refactors relacionados: (1) o front não cancela requests — `get`/`post` em `shared/api/client.ts` não aceitavam `signal`, nenhum `AbortController` existe no código (`grep` vazio), e o `signal` que o React Query já injeta em todo `queryFn` era ignorado; (2) `useCriarEmpenho` acopla no mesmo arquivo orquestração de negócio (atualizar cache de sessão, invalidar a query do agregado) + wiring de React Query + chamada de transporte, sem espelhar a separação `domain`/`application`/`infra` que o backend já pratica (`execucao-application/RegistrarEmpenho.java`, `ConsultarExecucaoOrcamentaria.java` — nomeados verbo imperativo + objeto, sem sufixo `UseCase`). Esta é a **redelivery real** de RAZ-137 (ADR-0040): uma execução anterior implementou exatamente esta decisão na cópia de workspace desconectada do Paperclip (`/Users/.../.paperclip/instances/default/workspaces/<agentId>`), marcou `done`, e o trabalho nunca chegou a este repo — confirmado via `codebase.effectiveLocalFolder`, RAZ-184/RAZ-187 tracking o gap. Esta ADR e o código associado substituem aquele trabalho fantasma pelo real, contra o client/contrato desta base (`ente` no path, `GovbrContexto`, `parseJsonPreservingMoney`), não contra o `client.ts` genérico da cópia desconectada.
- **Decisão:**
  1. **`get`/`post` aceitam `RequestOptions{ signal }` e repassam ao `fetch`.** Todo método de `execucaoClient`/`razaoClient` ganha um parâmetro final opcional `options?: RequestOptions` encaminhado até o `fetch` — cancelar o request é cancelar o `fetch` de verdade, não parar de atualizar estado local depois que a resposta já chegou.
  2. **Hooks de query encaminham o `signal` que o próprio React Query fornece.** `queryFn: ({ signal }) => casoDeUso(..., { signal })` — trocar de tela/parâmetro antes da resposta cancela o fetch em andamento (`useExecucaoOrcamentaria` é o primeiro a aplicar isso; é o padrão para toda consulta nova).
  3. **Mutations não ganham `signal` automático do React Query v5** — sem paridade query/mutation aqui. Se uma mutation de escrita precisar ser cancelável, quem chama gerencia seu próprio `AbortController` explicitamente; não presumido em `useCriarEmpenho`.
  4. **Lógica de negócio migra para caso de uso puro, por operação, em `features/<feature>/application/`** — sem `react`/`@tanstack/react-query` importado, nomeado verbo imperativo + objeto espelhando o nome do use case real do backend (`registrarEmpenho` ↔ `RegistrarEmpenho.java`, `consultarExecucaoOrcamentaria` ↔ `ConsultarExecucaoOrcamentaria.java`). O hook em `features/<feature>/api/` fica fino: monta `queryKey`/`mutationFn`, repassa `signal`, cuida de invalidação por evento de domínio (React-Query-específico, continua no hook — ADR-0034 item 9). Testável sem React: `registrarEmpenho.test.ts`/`consultarExecucaoOrcamentaria.test.ts` chamam a função direto contra o MSW existente, sem `@testing-library/react`.
  5. **Fronteira `application/` → sem React imposta por teste (não por lint).** `oxlint` (o linter real deste repo, não ESLint) continua sem um equivalente a `no-restricted-imports` (reconfirmado em oxlint 1.71: `npx oxlint --rules` não lista nada em "import"). Em vez de esperar a evolução do linter, a fronteira é imposta com dentes por um teste tool-agnóstico — `frontend/src/architecture/fronteira-application-sem-react.test.ts` (RAZ-192) — que varre `features/*/application/**` (código de produção) e falha se algum caso de uso importar `react`, `react-dom` ou `@tanstack/react-query` (specifier exato ou subpath; lookalikes como `react-router-dom`/`react-hook-form` passam). O próprio teste assere que varreu ≥1 arquivo, para não virar placebo se o layout mudar. Espelha o ArchUnit do backend (`guardrails:architecture-tests`, ex.: `registro_usa_clock_injetado`) e roda em `npm test`.
- **Consequências:**
  - **+** Cancelamento de ponta a ponta: navegar para outro período/tela antes do `GET /execucao/orcamentaria` responder cancela o `fetch` real.
  - **+** `registrarEmpenho`/`consultarExecucaoOrcamentaria` testáveis sem montar árvore React — mais rápido de rodar, mais fácil de isolar lógica de negócio de efeito de framework.
  - **+** Nomenclatura do caso de uso no front espelha 1:1 a classe do backend — reduz a distância entre "o que a tela faz" e "o que o `execucao-application` faz" para quem navega os dois lados.
  - **−** Todo hook de feature vira dois arquivos (hook + caso de uso) em vez de um — aceito porque a coupling que a issue aponta (`useCriarEmpenho` fazendo três coisas num arquivo só) é exatamente o que a separação resolve; um hook que nunca crescer lógica própria continua barato mesmo em dois arquivos pequenos.
  - **+** Fronteira `application/` sem React imposta com dentes por teste (item 5, RAZ-192) — um import de `react`/`react-dom`/`@tanstack/react-query` num caso de uso quebra `npm test`, sem depender de revisão humana notar. `oxlint` segue sem a regra, mas o enforcement não fica refém da evolução do linter.
  - **−** Esta ADR não mexeu em `razaoClient` (saldo/balancete/contas) além de adicionar `options?: RequestOptions` às assinaturas — o gap de schema de `razaoClient` (tipos referenciados que não existem em `openapi/contrato-provisorio.yaml`, deixando `npm run build`/`tsc -b` vermelho) é **RAZ-182** (outro agente, em andamento no momento desta entrega) e está fora do escopo deste ADR; verificação aqui usou `npm test` + `oxlint` (ambos verdes), não `npm run build`, precisamente por essa causa pré-existente e não relacionada.
- **Alternativas consideradas:** manter o `signal` só no nível do hook (sem descer até `get`/`post`) — rejeitada, pois deixaria o `fetch` real correndo até o fim mesmo com a UI já tendo descartado a resposta, o oposto do que RAZ-137 pede; adicionar uma lib de cancelamento (ex.: axios `CancelToken`) — rejeitada, `AbortController`/`AbortSignal` nativos já resolvem sem nova dependência; sufixar caso de uso com `UseCase` (`RegistrarEmpenhoUseCase`) — rejeitada para manter simetria exata com a convenção já estabelecida no backend real (`RegistrarEmpenho`, sem sufixo).
