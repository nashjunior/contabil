# ADR-0059 · Transparência ativa (F1): consumidor real do outbox projeta read model público append-only; portal + API de dados abertos (JSON/CSV) sobre ele, com guarda de mascaramento que quebra o build

- **Status:** Proposta
- **Data:** 2026-08-02
- **Gate:** ratificação Proposta→Aceita condicionada a (a) os **3 accepts formais** do gate de RFC [RAZ-272](../../transversais/03-transparencia.md) — **✅ concluído em 2026-08-02**: Segurança (Solange) 16:25, PM (Renata) 23:07 e UX (Paula) 23:11 — os três cartões `request_confirmation` aceitos pelo board; e (b) fechar a **revalidação da citação legal** dos arts. 7º/8º do Decreto 10.540/2020 na fonte oficial (via `pesquisar-fonte`), pendência pré-existente do doc [transversais/03](../../transversais/03-transparencia.md) — **ainda aberta**. Condição (a) destrava a **implementação** (RAZ-273, designada a Gustavo em 2026-08-02); (b) bloqueia apenas o *texto final* (Status→Aceita) deste ADR, **não** a implementação.
- **Contexto:** A transparência ativa (LRF art. 48/48-A — LC 131/2009; Decreto 10.540/2020 art. 3º e 9º; LAI 12.527/2011 art. 8º; Lei 14.129/2021) é obrigatória de F1. O pipeline **já existe** e não deve ser reconstruído (confirmado no repo em `fe4ba19`, camada a camada):
  - **Produtor** `PublicadorTransparenciaExecucao` (execucao-application) emite, **na mesma transação** do fato, os eventos `execucao.empenho.registrado.v1` / `.liquidacao.registrada.v1` / `.pagamento.registrado.v1` com **payload público já minimizado e mascarado** (`ServicoMascaramento`, `Audiencia.PORTAL_PUBLICO`: CPF `***.456.***-**`, CNPJ íntegro) e computa `publicarAte` = 1º dia útil subsequente (SLA Decreto 10.540 art. 3º).
  - **Outbox garantido** ([ADR-0004](./0004-outbox-idempotente.md)): `ServicoEntrega.enqueue` → `OutboxEntregaWorker` (reclaim/lock, retry com backoff, DLQ, métricas `siafic.publicacao.transparencia.*`).
  - **Buraco:** o worker chama `BrokerEntrega.publicar(...)`, cuja única implementação é o **stub fail-closed** `BrokerEntregaIndisponivel` (`plataforma-infra`), que lança `IllegalStateException`. Nada é publicado — este é o alvo de F1.
- **Decisão:**
  - **D1 — Consumidor real = projetor para read model público, não broker externo (F1).** A implementação real de `BrokerEntrega` (destino `transparencia`) **projeta o payload já mascarado** numa tabela read-model, substituindo o stub. Preserva idempotência/retry/DLQ do outbox ([ADR-0004](./0004-outbox-idempotente.md)/[ADR-0011](./0011-idempotencia-ponta-a-ponta.md)). Broker externo (fila/mensageria) fica **fora de F1** (YAGNI); o seam `BrokerEntrega` continua trocável.
  - **D2 — Read model público append-only ([ADR-0007](./0007-read-models-cqrs.md)/CQRS-lite), série histórica nunca sobrescrita.** `transparencia_publicacao(ente_id, tipo_evento, recurso, sequencia, publicado_em, publicar_ate, payload_json jsonb, chave_idempotencia unique)`. Nova versão do mesmo `recurso` = **nova linha** (consulta pega a corrente + expõe histórico). Índices para os filtros exigidos (credor, órgão, período, função, nº empenho/contrato). É a **única fonte de leitura** do portal e da API — **nenhum** dos dois toca o razão/tabelas transacionais.
  - **D3 — Fronteira de acesso público é física, não só lógica.** Papel/role de banco **somente-SELECT** restrito ao(s) read-model(s) público(s); RLS por `ente_id` ([ADR-0003](./0003-multi-tenant-rls.md)) mantida; escopo do ente vem do **path** (`/transparencia/{ente}/...`), sem sessão/cadastro. O acesso interno íntegro segue por RBAC + trilha de leitura, **canal separado**. O público **nunca** tem caminho de query para dado sensível — porque o read model só contém payload mascarado.
  - **D4 — API de dados abertos + borda.** REST sobre o read model: **JSON e CSV** (negociação por `?formato=csv`/Accept), **paginação keyset**, filtros/ordenação, totalizações; **carimbo de última atualização** e link de integridade. **Download de bases completas = arquivo versionado servido por CDN**, não varredura da API. Borda (Decreto 10.540 art. 9º — disponibilidade): **rate-limit/quota** por IP/cliente + **cache/CDN** para absorver pico, **sem exigir cadastro** nem bloquear download legítimo. **Dicionário de dados/metadados** como endpoint + doc estático.
  - **D5 — Mascaramento uniforme com guarda que quebra o build (defesa em profundidade).** Mascaramento no produtor **e** read model só guarda payload mascarado; **além disso**, um teste de regressão passa fixtures representativas (CPF, RG, endereço, conta bancária, remuneração nominal, CNPJ) por **todos** os serializadores públicos (DTO portal, JSON, CSV, bulk) e **falha o build** se vazar campo não-mascarado. Espelha o padrão ArchUnit já usado no backend. Regra de campo: CNPJ e **remuneração nominal permitidos** (STF Tema 483); **RG/endereço/conta bancária suprimidos**; CPF mascarado.
  - **Refinamentos vinculantes incorporados no gate RAZ-272** (viram critério de aceite de RAZ-273):
    - **[Seg-1]** A guarda de D5 vale em **todos** os serializadores públicos, **incluindo o download bulk/CSV**; o role público/portal **não** pode ter permissão de leitura sobre tabelas transacionais ou visões internas com PII íntegra. Se cair no código, volta como `reject` no review de implementação.
    - **[UX-1]** Estágio/tipo de evento como **enum estável** no `payload_json` (valor semântico fixo empenhado/liquidado/pago), não rótulo em texto livre — a UI acessível monta badge/ARIA a partir dele.
    - **[UX-2]** **Mesmos parâmetros de filtro** entre o endpoint de totalização e o de detalhe (drill-down totalização→documento, não duas telas divergentes).
    - **[UX-3]** **Ordenação padrão explícita e documentada** (mais recente primeiro por data) + lista dos campos ordenáveis.
    - **[UX-4]** **Metadados de posição** na paginação keyset (ao menos indicador "há mais"/contagem aproximada) — paginação acessível precisa anunciar posição ao leitor de tela.
    - **[UX-5]** **Dicionário de dados legível por humano** (HTML/markdown, linguagem simples + exemplo por campo, incluindo a notação de máscara `***.456.***-**`), não só schema técnico (OpenAPI/JSON Schema) — LAI art. 8º exige formato compreensível.
    - **[PM-1]** SLA ≤ 1º dia útil vira critério de aceite **testável**: teste de integração que **falha** se `publicado_em > publicar_ate`, + métrica/alerta de estouro reusando `siafic.publicacao.transparencia.*` (não basta o cálculo de `publicarAte` existir).
- **Escopo F1 vs. adiado:**
  - **F1 (RAZ-273):** despesa (empenho/liquidação/pagamento) + receita quando o produtor de receita existir; busca/filtros/série histórica; JSON/CSV/API + dicionário; borda rate-limit + CDN; guarda de mascaramento (D5). O contrato de dados fecha agora; as **telas do portal** (WCAG 2.2 AA) são **gate de UX separado** — Paula entrega fluxo/wireframe sobre este contrato **antes** de qualquer código de tela, e RAZ-273 **não** empacota UI sem esse pass.
  - **Adiado (F2, apontar não construir):** painéis analíticos; versionamento de dados abertos; integração fina SICONFI/TCE. **Remuneração individualizada nominal** depende da folha (estruturante). A **"carga CSV de contingência" de remuneração** citada de passagem na RFC **não é escopo de RAZ-273**: se for necessária para o go-live do ente-piloto, é decisão própria (toca remuneração nominal — PII/LGPD) e **retorna ao gate de Segurança**, não entra como side-effect.
- **Consequências:** fecha o consumidor do outbox sem criar pipeline novo; portal e API leem só do read model, isolados do OLTP do razão (consistência eventual dentro do SLA de 1 dia útil, [ADR-0007](./0007-read-models-cqrs.md)); a fronteira público×interno é física (role SELECT-only + RLS + payload mascarado), reduzindo a superfície de vazamento a um teste que quebra o build; a borda (quota/CDN) mitiga raspagem/reidentificação em massa sem cadastro (preserva transparência ativa). Custo: uma tabela read-model append-only a manter e reconstruir; o portal UI fica sequenciado atrás de um gate de UX (mais latência de entrega, menos retrabalho). A implementação (RAZ-273) nasce `blockedBy` RAZ-272 e só destrava com os 3 accepts formais.
- **Alternativas consideradas:**
  - **Broker externo real (fila/mensageria) como consumidor** — rejeitado para F1: YAGNI; nenhum consumidor externo existe; o read model atende o portal/API e o seam `BrokerEntrega` permanece trocável se surgir demanda.
  - **Portal/API lendo direto do razão/tabelas transacionais** — rejeitado: contenção no OLTP ([ADR-0007](./0007-read-models-cqrs.md)) e, sobretudo, exporia caminho de query a dado íntegro; a fronteira física (D3) só é possível com read model dedicado mascarado.
  - **Mascarar só no produtor (confiar no evento)** — rejeitado: canal único de defesa; D5 adiciona a guarda que quebra o build em todos os serializadores (defesa em profundidade), exigência de Segurança.
  - **Varredura da API para bulk** — rejeitado: arquivo versionado por CDN é mais barato, cacheável e não compete com a borda rate-limited da API interativa.
