# ADR-0031 · Frontend: pipeline de design tokens (RAZ-100 → tema tipado)

- **Status:** Aceita
- **Data:** 2026-07-26
- **Contexto:** RAZ-119 pede que o front consuma os tokens da RAZ-100 (Paula) como **fonte única** — nenhuma cor/spacing hardcoded em componente. RAZ-100 está `done`: biblioteca Figma (`fileKey ObQu8oMQ0cEGbONMXgpuLU`, [ADR-0026](./0026-design-system-figma-decisoes-estruturais.md)) com tokens semânticos documentados em [design-system-tokens-componentes.md](../design-system-tokens-componentes.md) §1 — camada `Color` (bg/text/border/brand/state/pii), `Spacing`/`Radius`, text styles. Não existe export DTCG/JSON versionado no repo (só o Figma + a doc markdown); a sessão MCP do Figma disponível nesta execução só expõe a página `Cover` do arquivo (não `Foundations`), então os valores hexadecimais exatos dos primitivos (`neutral`/`success`/`warning`/`danger`, 12/7/7/7 passos) não puderam ser extraídos automaticamente — só `brand/500 = #2F6CAE` está documentado em texto.
- **Decisão:**
  1. **Tokens semânticos (não primitivos) são a fonte que o código consome** — mesma regra que a Paula já aplicou no Figma (primitivos ocultos de todo picker, só a camada semântica exposta). `frontend/tokens/*.tokens.json` usa os **nomes exatos** de §1.2 da doc (`bg/canvas`, `text/primary`, `brand/default`, `state/success-{bg,fg,border}`, `pii/mask-{bg,fg}` etc.) e a escala exata de §1.3/§1.4 (spacing `2xs..3xl` = 2/4/8/12/16/24/32/48px; radius `none..full` = 0/4/8/12/999; type scale `Heading/H1..Money/Emphasis`, família Inter). Formato DTCG (`$value`/`$type`), o que qualquer export futuro do Tokens Studio produz sem fricção.
  2. **Style Dictionary** builda `tokens/*.tokens.json` → `frontend/src/shared/tokens/theme.ts` (tema tipado, `as const`) + `theme.css` (custom properties). Nenhum dos dois é editado à mão — artefato de build (`npm run tokens:build`), gitignorado.
  3. **Valores exatos dos primitivos ficam PENDENTES de sincronização com o Figma real** — `brand/500 = #2F6CAE` (documentado) é o único primitivo com hex confirmado; os demais (neutral/success/warning/danger) usam uma escala provisória internamente consistente (mesmo matiz institucional sóbrio descrito na doc), com cada arquivo `tokens/*.tokens.json` marcado `"$description": "Nomes/estrutura = RAZ-100 real; hex exato pendente de sync com o Figma (fileKey ObQu8oMQ0cEGbONMXgpuLU, página Foundations)"`. Isso é diferente de "RAZ-100 não entregue" (não é o caso) — é um gap de **sincronização automatizada** Figma→código, registrado como próximo passo (ver Consequências), não um bloqueio para o Bruno começar: os *nomes* semânticos que o componente usa (`theme.color.semantic["brand-default"]` etc.) não mudam quando o hex exato for sincronizado.
  4. **Gate de contraste AA automatizado** (`scripts/check-contrast.mjs`, roda no `tokens:build`): falha o build se um par `*-fg`/`*-bg` declarado em `tokens/_meta/contrast-pairs.json` cair abaixo de 4.5:1. A doc RAZ-100 já atesta validação manual (≥7:1 nos badges/chips, ~5.4:1 em `text/on-brand` sobre `brand/default`) — o gate automatizado é a garantia de que isso não regride silenciosamente quando o sync do primitivo real acontecer.
- **Consequências:**
  - **+** Nomenclatura já é a real (Figma); trocar só os valores hex dos primitivos quando sincronizados não muda nenhum componente (consomem o nome semântico).
  - **+** Contraste AA vira gate de CI, não depende de revisão manual lembrar de checar a cada novo par.
  - **−** Sync automatizado Figma→`tokens/*.tokens.json` não existe ainda (Tokens Studio/Figma Variables REST API); é trabalho de integração futuro, não decidido aqui. Enquanto isso, qualquer token novo criado na Paula precisa ser copiado à mão para o JSON (mesmo risco de drift que qualquer handoff manual) — o pipeline de build já criado remove a fricção do lado do código, o lado Figma→JSON é o gap restante.
  - **−** Hex exato dos primitivos pendente (ver Decisão 3) — quem tiver acesso de leitura ao Figma real deve substituir os valores em `tokens/*.tokens.json` assim que possível; issue de acompanhamento sinalizada no comentário da RAZ-119.
- **Alternativas consideradas:** Bloquear o scaffold até um humano extrair os hex exatos do Figma (rejeitada — RAZ-120/Bruno está em execução agora, dependente desta ADR; bloquear custa mais que corrigir 4 valores hex depois, já que nenhum componente referencia hex bruto); tokens primitivos expostos ao componente (rejeitada — contraria a decisão já tomada pela Paula no ADR-0026 de esconder primitivos de quem monta tela).

## Atualização (RAZ-125)

Decisão 3 (hex dos primitivos pendente) está **majoritariamente resolvida**. A sessão MCP do Figma conectada por OAuth (`claude_ai_Figma`) continua só expondo a página `Cover` (mesma limitação do contexto original), mas o token do servidor `figma-developer-mcp` já presente em `.mcp.json` (escopo `file_content:read`) permite chamar a **REST API do Figma diretamente** (`GET /v1/files/:key`, `GET /v1/files/:key/nodes?ids=...`) — esse caminho **não** está sujeito à mesma limitação de página e retorna a árvore completa do documento, incluindo `Foundations` (id `2:50`).

A coleção `Primitives` (Figma Variables) continua inacessível diretamente — `GET /v1/files/:key/variables/local` retorna 403 (`falta o escopo file_variables:read`, normalmente Enterprise-only). Mas a página `Foundations` desenha 35 swatches da camada semântica (`Color`), cada um com fill resolvido para o valor final do primitivo que ele referencia (`boundVariables` + `fills[].color` do node). Lendo os 35 fills e revertendo pelo alias documentado em [design-system-tokens-componentes.md §1.2](../design-system-tokens-componentes.md) dá o hex real de **9/12 passos de `neutral`, 5/9 de `brand`, 3/7 cada de `success`/`warning`/`danger`** — exatamente o conjunto que `frontend/tokens/color.tokens.json` já usava. `brand.500` resolvido por essa via bateu exatamente com o valor já documentado em texto (`#2F6CAE`), confirmando o método.

`frontend/tokens/color.tokens.json` foi atualizado com esses valores reais (todo `$description` cita a variável Figma de origem); o gate de contraste (`npm run tokens:build`) foi revalidado e todos os 8 pares continuam ≥4.5:1 (o par mais apertado, `text/on-brand` sobre `brand/default`, ficou em 5.42:1 — bate com o ~5.4:1 já documentado pela Paula). `neutral.200` (não referenciado por nenhum token semântico, logo sem fill para ler) foi inferido por continuidade — os outros 9 passos de `neutral` batem exatamente com a paleta `slate` do Tailwind — e fica marcado `$description` como não confirmado, não como real. Passos de `brand`/`success`/`warning`/`danger` sem alias semântico (a paleta institucional não bate com nenhuma escala conhecida) não foram preenchidos.

**Gap remanescente:** os passos do primitivo sem consumidor semântico (parte de `neutral`, maioria de `brand`/`success`/`warning`/`danger` até completar 12/9/7/7/7) exigem a Variables REST API com escopo correto ou um export manual via Tokens Studio — ver `frontend/tokens/README.md`. Como primitivos ficam ocultos da camada semântica (ADR-0026), esse resíduo não bloqueia nenhum componente atual.
