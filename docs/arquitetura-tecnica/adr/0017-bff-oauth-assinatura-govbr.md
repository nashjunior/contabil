# ADR-0017 · BFF OAuth2 do signatario para Assinatura gov.br

- **Status:** Aceita
- **Data:** 2026-07-19
- **Contexto:** A assinatura gov.br avancada (ADR-0008, RAZ-11) ja possui o adapter HTTP real para `assinarPKCS7`, mas ele recebe o token OAuth2 do signatario por `Supplier<String>`. Faltava a superficie web/BFF que conduz o fluxo `authorization_code` interativo contra o gov.br (`cas.staging.iti.br/oauth2.0/authorize`) e entrega um token de usuario ao adapter. O projeto usa Spring Boot no `bootstrap` como composition root (ADR-0012) e a borda HTTP nao deve entrar nos modulos puros de dominio/application (ADR-0002). Tenant efetivo continua vindo de contrato verificado e RLS (ADR-0003); a assinatura do documento carrega `ente` explicitamente (ADR-0015).
- **Decisao:** O BFF web de assinatura fica no modulo `bootstrap`, como borda HTTP da aplicacao executavel. O fluxo usa Spring MVC, `HttpSession` server-side e PKCE: `GET /assinatura/oauth/iniciar` cria `state` e `code_verifier`, associa-os ao `ente` verificado da sessao autenticada, e redireciona para o authorization endpoint gov.br com escopos `sign` e `signature_session`. `GET /assinatura/oauth/callback` valida o `state` na sessao, troca `code` por `access_token` no token endpoint configurado, autentica a assercao gov.br pelo port `ServicoIdentidade`, confere que o `ente` retornado pelo IAM e igual ao `ente` do fluxo pendente, grava a `ServicoIdentidade.Sessao` verificada no `HttpSession` e so entao grava o token da assinatura. O `Supplier<String>` injetavel le o token da sessao HTTP corrente e falha fechado se nao houver token valido.
- **Consequencias:** O codigo de dominio e o adapter `ProvedorAssinaturaGovBrHttp` nao conhecem Spring MVC nem sessao web. A protecao CSRF do OAuth fica em `state` server-side, e o `code_verifier` nunca sai da sessao. Credenciais (`client_id`/`client_secret`) entram por ambiente/cofre; sem elas o endpoint falha fechado no inicio do fluxo, preservando o startup local. A identidade nominal do signatario e o tenant nao sao aceitos por header/query/body cru: devem vir do IAM gov.br/ICP-Brasil; o resolvedor padrao le `ServicoIdentidade.Sessao` do `HttpSession` e falha fechado se a sessao estiver ausente, expirada ou sem MFA concluido. Este BFF armazena server-side o token OAuth da assinatura, o `ente` de escopo do fluxo e a sessao IAM verificada retornada pelo port de identidade; divergencia de tenant no callback e recusada antes de trocar a sessao ou expor o token ao supplier. Teste ponta-a-ponta real segue bloqueado ate haver aplicacao OAuth2 registrada no gov.br staging, mas a mecanica redirect/callback/token/IAM e testavel com stub local.
- **Alternativas consideradas:** Colocar controller em `plataforma-infra` (rejeitado: mistura adapter transversal com composition root HTTP); fluxo stateless com `state` assinado contendo `code_verifier` (rejeitado para F0: aumenta superficie criptografica/segredo na borda sem necessidade enquanto `HttpSession` atende ao BFF); passar token diretamente por parametro para o servico de assinatura (rejeitado: vazaria token para contratos de dominio/application e quebraria o seam ja definido por RAZ-11).
